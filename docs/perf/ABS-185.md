# ABS-185: how fast agent plugins read their agents' output

Agents are plugins now: an agent plugin's script, in a JavaScriptCore context
inside AbstractCore, turns each line its agent prints into `AgentEvent`s. Every
chat's log is folded again when it opens, on another Mac and in history search,
so this is measured against the Swift parsers the scripts replace, on today's
recorded fixtures (`Packages/AbstractCore/Tests/AbstractCoreTests/Fixtures`),
read many times over.

- **Replay**: lines handed to the script 512 at a time, as `ChatStream` replays a log.
- **Live**: one line at a time, as a running chat reads it.

Release build (Apple silicon, `-c release -Xswiftc -enable-testing`), per 100 lines:

| Agent | Lines | Swift parser | Plugin, replay | Plugin, live |
|---|---|---|---|---|
| OpenCode (4 fixtures × 200) | 3,400 | 3.73 ms | 1.28 ms (0.34×) | 2.42 ms (0.65×) |
| Muse Code (10 fixtures × 200) | 60,400 | 11.30 ms | 2.07 ms (0.18×) | 3.55 ms (0.31×) |

Debug build (`swift test --filter AgentParseBenchmark`), per 100 lines:

| Agent | Swift parser | Plugin, replay | Plugin, live |
|---|---|---|---|
| OpenCode | 8.26 ms | 1.50 ms | 2.83 ms |
| Muse Code | 25.51 ms | 2.14 ms | 3.56 ms |

The scripts are faster than the code they replace: `JSON.parse` is quicker than
decoding into `JSONValue`, and a batch crosses into the script once. Handing
events back (JavaScript objects to `JSONValue` to `AgentEvent`) is most of what
a plugin line costs.

`AgentParseBenchmark` keeps this true: replay must stay within 4× of the Swift
parser measured beside it, loose enough for a busy CI Mac. Each plugin's
calls hold one lock, so one plugin's chats parse a line at a time between them;
another plugin's never wait on it.
