# ABS-146 — One icon picker for projects, profiles, workflows, and plugin fields

## Decision

Extract the existing project picker into a native `IconPicker(value:defaultLabel:onChange:)` and `IconTile(value:name:context:size:)`. The picker keeps its symbol grid, color swatches, image upload, and **Use Default** action. An `IconValue` in `AbstractCore` is three optional fields: `symbol` (SF Symbol name), `color` (one of the current palette tokens), and `imagePath` (a host-local managed PNG path). All nil means default. A color without a symbol is valid. A selected image wins visually; choosing a symbol or color clears it, as today's project picker does. Preserve a saved symbol outside the current grid by showing its selected tile until changed. The Swift model may hold a path; **no plugin or remote payload receives that path**.

Use the same rounded tile, tint, symbol sizing, image crop, and accessibility name in every native surface. `IconTile` receives the owning context to choose the default: a project's GitHub-owner avatar when available, otherwise its name's initial; a profile's `person.crop.circle`; a workflow's `Workflow.defaultSymbol`; a plugin field's initial from its field label. The GitHub avatar is **only** a project default, never a property of `IconValue` and never used for other owners. An unavailable image falls back to the saved symbol/color, then that owner's default. This preserves the [current project precedence](../../Abstract/Features/ProjectSettings/ProjectIcon.swift#L38-L81) and [project icon actions](../../Abstract/Features/ProjectSettings/ProjectIcon.swift#L107-L202).

## Storage and migration

Keep projects' `icon_symbol`, `icon_color`, and `icon_image_path` columns. Add nullable `icon_color` and `icon_image_path` columns to profiles and workflows in one new migration; their existing `icon_symbol` columns already hold saved choices ([schema](../../Packages/AbstractCore/Sources/AbstractCore/Store/Store.swift#L721-L745), [workflow schema](../../Packages/AbstractCore/Sources/AbstractCore/Store/Store.swift#L795-L809)). Extend `AgentProfile`, `Workflow`, their row codecs, and tolerant Codable decoding with the two optional fields. `nil` is the default for old rows and snapshots; migrate no symbol text or file. Existing project paths remain valid. New uploads go to an owner-specific directory under Application Support, with random filenames and the same 256 px center crop; the existing project images remain in `ProjectIcons` until replaced. The host alone resolves paths. Save the new record before deleting its previous managed image; on save failure, discard the newly copied file and keep the old one. On reset, replacement, or owner deletion, remove only that owner's managed file, after a successful database change. On startup, remove orphaned managed files after checking all three tables and plugin icon records; never delete a path outside the managed directories. The current [project image store](../../Abstract/Features/ProjectSettings/ProjectSettingsSupport.swift#L202-L254) supplies crop and safe-delete behavior but needs transactional call sites (its current [mutations](../../Abstract/Features/ProjectSettings/ProjectSettingsSupport.swift#L28-L59) delete after a save that can fail).

For plugin fields, create a host-owned `plugin_icon_fields` table keyed by `(plugin_id, field_key)` with the same three fields. Its uploaded files live under `PluginIcons/<plugin id>/`; uninstall removes the rows and files. These are the plugin's own UI preferences, not project/profile/workflow records. Do not alter package/manifest icons automatically. Limit a key to 64 ASCII letters, digits, `_`, `.`, or `-`; limit fields per plugin (for example 32), to bound storage. `IconValue` is the one native renderer/storage contract; plugin JSON is a deliberately narrower view of it.

## Capability and data flow

| Actor / place | Request or source | Host operation and result | Boundary |
| --- | --- | --- | --- |
| Project, profile, workflow Settings | Native tile button | Native popover edits that owner's `IconValue`, including upload/reset | Only the selected record is saved. |
| Plugin main/placed screen | `AbstractPlugin.send("icon.get", {key})` | Return `{symbol, color, imageHandle, previewDataURL}` for this plugin's field, or the default value | No global icon list, owner ID, or file path. |
| Plugin main/placed screen | `AbstractPlugin.send("icon.choose", {key, anchor})` after a user click | Clamp the element rectangle to this `WKWebView`; show the same native picker at that rectangle; commit on a selection and reply with the new value/preview. Cancel replies with the old value. | No `profiles.write`, project write, file grant, or general storage grant. Never accept a target owner or a supplied file URL. |
| Plugin background script | Either icon request | Reject | No window or user gesture to anchor a picker. |
| Paired Mac / phone | Host snapshot | Send bounded image bytes by owner ID, as project icons already do; fall back to symbol/color when bytes are absent. | Local `imagePath` is never opened on the viewer. |

`imageHandle` is an opaque, unguessable token scoped to the plugin and field, rotated on replacement. It is only an identity for the currently returned image, not a URL, path, or permission to fetch a file. `previewDataURL` is a host-rendered, size-limited PNG (including SF Symbols, which web CSS cannot draw); it is ephemeral and not stored in plugin storage. A plugin calls `icon.get` again when its view reloads. The host validates the key, message size and rate, enabled plugin, screen placement, and a recent pointer or keyboard activation for `icon.choose`; the native panel is the only upload source. It reads/writes the field under the connection's own `plugin.id`, so a forged key or handle cannot reach another plugin or an Abstract record. Invalid anchors are clamped to the web view, and an already open picker refuses a second request. On disable/dismantle, dismiss it without saving. Add bridge outcomes in [PluginBridge](../../Packages/AbstractCore/Sources/AbstractCore/Plugins/PluginBridge.swift#L7-L18) and route them through [PluginConnection](../../Abstract/Features/Plugins/PluginConnection.swift#L80-L101); the [web-view coordinator](../../Abstract/Features/Plugins/PluginHostView.swift#L90-L109) owns the native popover. The [shim](../../Abstract/Features/Plugins/PluginConnection.swift#L351-L375) already correlates replies by request ID. Keep API 1/2 compatibility by adding optional message types and feature detection in context, with no new broad manifest capability.

## Display and implementation seams

- Replace the two text menus and their separate symbol arrays in [Profiles Settings](../../Abstract/Features/Settings/ProfilesSettingsPane.swift#L127-L153) and [Workflows Settings](../../Abstract/Features/Settings/WorkflowsSettingsPane.swift#L97-L115). Replace their list/header symbols, and the profile symbol in the [workflow step editor](../../Abstract/Features/Settings/WorkflowsSettingsPane.swift#L203-L211), with the common tile. The symbol grid should include the union of existing project/profile/workflow choices, while keeping arbitrary saved symbols visible.
- Use the tile in [New Chat](../../Abstract/Features/Launcher/TaskLauncher.swift#L80-L99) and the [automation editor](../../Abstract/Features/Automations/AutomationEditor.swift#L790-L807). Use the current profile's tile on the [workflow strip](../../Abstract/Features/Chat/WorkflowStrip.swift#L18-L50) and any chat profile/workflow badge, resolving current records where available. A running chat's name/instructions remain its existing snapshot, so editing an icon does not change those. A deleted record falls back to its snapshot name and default tile.
- Keep project icons on chat rows (including remote rows) through [SidebarChats](../../Packages/AbstractCore/Sources/AbstractCore/Sessions/SidebarChats.swift#L78-L115). Extend the [remote snapshot](../../Packages/AbstractCore/Sources/AbstractCore/Remote/RemoteProtocol.swift#L300-L312) with optional bounded profile/workflow icon bytes, analogous to [project bytes](../../Abstract/Features/Remote/RemoteService.swift#L467-L485). Local and remote Mac Settings/New Chat/automations/steps render identical values. The phone's [profile type](../../mobile/src/types.ts#L18-L23) and [profile screens](../../mobile/src/profiles.ts#L3-L5) need color and bounded image data plus the same fallback; its existing [project icon view](../../mobile/src/ProjectIcon.tsx#L6) is the rendering pattern. A phone cannot launch the macOS upload panel or plugin picker; it displays the chosen icon and can keep its existing symbol-only editing until a native phone picker is built. Older peers that omit image bytes still show the symbol/color/default.
- In plugin screens, the plugin places a normal button/image using `previewDataURL` and invokes `icon.choose` from that button. The host owns selection and rendering. Package icons and sidebar contribution symbols remain manifest choices ([manifest symbols](../../Packages/AbstractCore/Sources/AbstractCore/Plugins/PluginManifest.swift#L272-L285)); this ticket concerns icon fields inside plugin views.

## Tests for the build ticket

Core tests: old profile/workflow rows and JSON decode with their exact symbols; default/color-only/image precedence; unknown saved symbols; migration round trip; save failure preserving old image; replacement/reset/delete cleanup and orphan sweep; remote snapshot bounds/fallback; plugin key validation, plugin isolation, background rejection, stale/forged handle rejection, and cancellation without a write. App tests or demo checks: one picker UI for each owner, a web button near each view edge opening the native popover, image preview after reload, and display parity across Settings, New Chat, automations, workflow steps, chat, remote Mac, and phone. The existing [remote icon limit](../../Packages/AbstractCore/Sources/AbstractCore/Remote/RemoteProtocol.swift#L348-L349) is a sensible per-image ceiling.

**Go.** The current native picker and sandboxed bridge support this without giving plugins file or profile write access. No disposable prototype is needed; popover anchoring can be verified in the build ticket's app check.
