# ABS-167 — A recognizable indicator for every CLI, MCP server, and tool in chats

## Decision

Add one pure resolver in `AbstractCore`, `ToolIndicator.resolve(name:input:)`, over a small data-driven catalog. It takes only what every tool row already has — [`ToolCall.name` and `ToolCall.input`](../../Packages/AbstractCore/Sources/AbstractCore/Sessions/Timeline.swift#L146-L159) — and returns `.brand(id)`, `.mcpServer(name)` (a monogram tile), `.kind(symbol)` (today's SF Symbol), or `.generic`. No new stream fields, no storage, no protocol change, no runtime fetching. Mac rows render the result in the existing 16×16 slot in [`ToolIcon`](../../Abstract/Features/Chat/ToolCallViews.swift#L512-L538); brand glyphs are bundled monochrome SVGs drawn as templates, like the [provider logos](../../Abstract/Resources/Assets.xcassets/ProviderClaude.imageset/Contents.json) and the Octicon issue mark. Unknown tools always get the generic indicator, never a guessed brand. **Go; ABS-165 is size M.**

Old transcripts resolve from the same two fields, so history re-renders correctly with no migration.

## Mapping

First match wins:

1. **Skill use** ([`SkillUse.name`](../../Packages/AbstractCore/Sources/AbstractCore/Skills/SkillUse.swift#L6)) → `book.closed`, as today.
2. **Abstract's own MCP servers**, under any spelling → the Abstract mark. The three servers are [`abstract-code-history`](../../Packages/AbstractCore/Sources/AbstractCore/History/CodeHistory.swift#L9) (`code_history`, `chat_excerpt`; match via the existing [`CodeHistory.tool(inStreamName:)`](../../Packages/AbstractCore/Sources/AbstractCore/History/CodeHistory.swift#L28-L35)), [`abstract-branch`](../../Packages/AbstractCore/Sources/AbstractCore/CLI/BranchMCPServer.swift#L5) (`name_branch`), and plugin tools on [`abstract-plugins`](../../Packages/AbstractCore/Sources/AbstractCore/Plugins/PluginTools.swift#L106) — plugin tools resolve further in step 3 and only fall back to the Abstract mark when the plugin is unknown (uninstalled since the chat ran).
3. **Plugin tools** ([`PluginTools.toolName(inStreamName:)`](../../Packages/AbstractCore/Sources/AbstractCore/Plugins/PluginTools.swift#L174-L179)) → look the published tool up in [`PluginToolLabels`](../../Abstract/App/AppModel+PluginTools.swift#L101) to get its plugin id. An official plugin id in the catalog (`sh.abstract.github`, `sh.abstract.bitbucket`, `sh.abstract.linear`, `sh.abstract.jira`) shows that brand; any other plugin shows `puzzlepiece.extension`, as today. Never infer a brand from a tool's name text.
4. **Other MCP calls** → parse the server segment: `mcp__<server>__<tool>` directly; the OpenCode `<server>_<tool>` form only when `<server>` exactly matches a catalog alias or one of Abstract's server names. A catalog alias (exact, lowercased; also accept the alias with a `-mcp` or `mcp-` affix, e.g. `linear-mcp`) shows that brand. Any other server shows `.mcpServer(name)`: a rounded tile with the server name's first letter, tinted from the existing icon palette by a stable hash of the name — recognizable and stable per server, and not a brand claim.
5. **Shell commands** (`ToolKind == .command`) → parse the command text (below) to a catalog brand or kind; no hit means `terminal`.
6. **Built-in tools** → today's symbol table in [`ToolPresentation.symbol`](../../Abstract/Features/Chat/ToolCallViews.swift#L805-L821), unchanged, including the file icon for edits.
7. **Anything else** → `.generic` (`wrench.and.screwdriver`).

### Command parsing

Input is the unwrapped command: reuse [`ToolPresentation.command` / `unwrapShell`](../../Abstract/Features/Chat/ToolCallViews.swift#L915-L935), moved next to the resolver so Mac and phone share one definition. Then:

- Split into segments on `&&`, `||`, `;`, `|`, and newlines outside quotes (a small scanner honoring `'…'`, `"…"`, and backslash escapes; no variable or `$()` expansion — a token containing `$` or a backtick makes its segment unresolvable). Try segments left to right; the **first catalog hit wins**, so `cd app && gh pr list | jq .` shows GitHub. No hit anywhere → `terminal`.
- Per segment: tokenize on whitespace outside quotes and strip the quotes. Drop leading `(` characters. Then strip, in order, any number of: environment assignments (`^[A-Za-z_][A-Za-z0-9_]*=`) and **transparent wrappers** — `env` (plus its assignments and `-i`/`-u NAME`), `sudo` (plus `-E -n -s -H -u USER -g GROUP`; an unrecognized `sudo`/`env` flag abandons the segment rather than guessing), `command`, `builtin`, `exec`, `nohup`, `time`, `nice` (plus `-n N`), and `xargs` (plus `-0 -I NAME -n N -P N`; same abandon-on-unknown-flag rule). A nested `sh|bash|zsh -c "…"` recurses into the quoted string, one level.
- **Runner wrappers** look through only when the next token itself resolves to a catalog entry; otherwise the runner's own brand stands: `npx`, `bunx`, `npm exec`, `pnpm dlx|exec`, `yarn dlx|exec`, `uv run|tool run`, `uvx`, `pipx run`, `poetry run`, `bundle exec`. So `uv run pytest` shows pytest, `npx some-tool` shows npm, `pnpm test` shows pnpm (no look-through without `dlx`/`exec`).
- The executable token is normalized: take the basename (`/usr/local/bin/gh`, `./node_modules/.bin/eslint`, `~/bin/linear` → `gh`, `eslint`, `linear`), lowercase it, and match **exactly** against catalog keys — no prefix or fuzzy matching. Only two entries also read the first argument: `acli jira …` → Jira (any other `acli` product → generic, since `acli` is Atlassian-wide), and the runner forms above.
- An executable that is only an argument never matches: `echo linear`, `grep gh file`, `git log --grep=linear` stay generic/`git`.

## Icon sources and licensing

All chat-row brand glyphs are **monochrome templates**, tinted like today's symbols (`btTextTertiary`, stronger on hover). Brand colors are deliberately not used: color stays free to mean failed/running, and one asset serves light and dark. Solid silhouettes are the only style that reads at 13–14 px in the 16×16 slot; the full-color gradient Jira SVG already shipped in its plugin package stays for issue chips, not chat rows.

| SF Symbols | Kind rows, generic, plugin-generic, built-ins | Apple's, already the row style today. |

Rejected, with reasons: **MCP-server-provided icons** — `ToolCall` carries no server info and our own servers' `serverInfo` is name+version only ([history server](../../Packages/AbstractCore/Sources/AbstractCore/CLI/HistoryMCPServer.swift#L46)); plumbing server metadata into every row is the tool-plumbing change this spike excludes. **A manifest icon field for plugin tools** — worth doing later, but third-party plugins read fine with the puzzle glyph today; v1 needs no manifest change. **Runtime favicon/logo fetching** — excluded by the ticket; also slow, flaky, and a privacy leak from a transcript renderer.

## Fallback and state treatment

- **Generic fallback**: `.generic` is `wrench.and.screwdriver` (today's default); shell commands with no catalog hit keep `terminal`; unknown MCP servers get the letter monogram, which is recognizable without claiming a brand. No path in the resolver guesses.
- **Running**: the indicator does not change or spin. Running is already carried by the label shimmer ([`Shimmer`](../../Abstract/Features/Chat/ToolCallViews.swift#L544)); a moving icon would fight it.
- **Failed**: keep the resolved indicator — knowing *which* tool failed is the point of the icon — and overlay a small red exclamation badge at the slot's lower-right, alongside today's red "Failed" label. This replaces today's full-slot warning triangle ([`ToolIcon`](../../Abstract/Features/Chat/ToolCallViews.swift#L526-L527)). Skipped/blocked keep the indicator and their existing text labels.
- **Hover/approval**: hover still swaps the slot to the open/close chevron. Approval rows show the resolved indicator too (it helps the decision); the skill exception (never disguise a pending approval as skill use) is unchanged.
- **Folded runs**: a `CallRun` of commands shows the shared indicator when every call resolves to the same one, else `terminal`; explore runs are unchanged ([`CallRun`](../../Abstract/Features/Chat/ToolCallViews.swift#L469)). Expanded rows resolve individually as usual.
- **Words**: each indicator carries its label for help text and accessibility ("GitHub CLI", "Linear MCP server", "Abstract"). Verbs and targets do not change.

## Phone and remote parity

Resolution is a pure function of `(name, input)`, and both already cross to every surface — so there is **no RemoteProtocol change** and older peers are unaffected (they simply keep today's symbols). A remote Mac runs the same `ToolCallViews`. The phone mirrors the resolver in [`mobile/src/toolPresentation.ts`](../../mobile/src/toolPresentation.ts#L1), which already mirrors the Mac symbol/verb tables and renders through [`ChatWorkspace`](../../mobile/src/ChatWorkspace.tsx#L237) with the same failed → file → symbol precedence: add the catalog (executables, aliases, parser) there, render brand glyphs from the same Simple Icons path data as inline SVGs (the phone already renders bundled SVG file icons via [`FileIcon.tsx`](../../mobile/src/FileIcon.tsx)), the monogram tile as a plain view, and the failed badge as an overlay. Keep both catalogs in step the way the symbol tables are kept today, and share the test cases.

## Implementation and test seams

- **Core**: new `Packages/AbstractCore/Sources/AbstractCore/Sessions/ToolIndicator.swift` — catalog data, `resolve(name:input:)`, the segment/token scanner, and `unwrapShell` moved from the app target (`ToolPresentation.command` keeps calling it). Server-alias matching reuses [`CodeHistory.tool(inStreamName:)`](../../Packages/AbstractCore/Sources/AbstractCore/History/CodeHistory.swift#L28) and [`PluginTools.toolName(inStreamName:)`](../../Packages/AbstractCore/Sources/AbstractCore/Plugins/PluginTools.swift#L174) rather than re-parsing their spellings.
- **Mac**: `ToolIcon` gains a `ToolIndicator` (brand image / monogram / symbol / file icon, failed badge); `ToolCallView` and `CallRun` resolve once per row. Plugin-id → brand needs the plugin behind a published tool: [`PluginToolLabels`](../../Abstract/App/AppModel+PluginTools.swift#L101) already maps stream names to labels from [`PluginTools.all`](../../Packages/AbstractCore/Sources/AbstractCore/Plugins/PluginTools.swift#L121-L130), which carries `pluginId` — extend that lookup to expose the id.
- **Assets**: `ToolBrand*` imagesets + license files (above). No settings, no migration.
- **Phone**: catalog + resolver mirror in `toolPresentation.ts`, glyphs in a generated-from-the-same-SVGs map.

Tests for the build ticket (`ToolIndicatorTests` in AbstractCore, table-driven; mirror the cases on the phone): each catalog executable and alias; wrapped commands (`FOO=1 /usr/local/bin/gh pr list`, `sudo -E linear issue view`, `env NO_COLOR=1 bkt pr list`, `zsh -lc "gh …"` after unwrap, nested `bash -c '…'`); runners (`uv run pytest` → pytest, `npx tsc` → TypeScript, `npx unknown-tool` → npm, `pnpm test` → pnpm); chains and pipes (`cd x && gh pr list | jq` → GitHub, `make && make test` → hammer); wrong-brand guards (`echo linear`, `acli confluence …`, `git -c x=y log` → git, unknown flags after `sudo` → generic, `$GH pr list` → generic); MCP spellings per agent (Claude/Codex `mcp__linear__get_issue`, OpenCode `linear_get_issue`, unknown server → monogram with a stable hash, `mcp__abstract-plugins__<official>_<tool>` → that plugin's brand, uninstalled plugin → Abstract); Muse exec's empty input → generic; folded-run shared vs mixed indicators. App check: screenshots of a mixed transcript in light and dark, including a running and a failed brand row, at the real row size — that is the legibility proof, so no disposable prototype is needed now.

## Size for ABS-165

**M.** The parser and catalog are one focused Core file with table-driven tests; the rest is a contained `ToolIcon` change, an asset drop, and a phone mirror. It is not S because of the wrapper/chain edge cases and the two renderers; it is not L because nothing about tool execution, streams, storage, or the remote protocol changes.

**Go.** Every row already carries enough to resolve its indicator locally, the icon supply is CC0 with an in-repo precedent, and the only blind spot (Muse exec arguments) degrades to today's generic terminal instead of blocking the build.
