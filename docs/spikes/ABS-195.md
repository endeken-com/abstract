# ABS-195: Gemini transport and signed-in probe

Probed 2026-11-09 in the isolated ABS-195 worktree. Google Antigravity CLI (`agy`) 1.5.3 is the supported transport for the Gemini agent plugin. Its [headless reference](https://antigravity.google/docs/cli/headless/) documents the stream, tools, usage, and resume route; those shapes were also verified in a signed-in run. The old Gemini CLI transport remains blocked for this Mac's cached individual free-tier account.

## Authentication and model IDs

- Installed `gemini` 0.66.0 still fails before a turn with `IneligibleTierError`, `reasonCode: UNSUPPORTED_CLIENT`, and a direction to move to Antigravity. This reproduces the blocker noted in [ABS-90](ABS-90.md). Gemini CLI's [authentication guide](https://geminicli.com/docs/get-started/authentication/) still describes personal Google sign-in, but this account cannot use that client.
- The user signed into `agy` interactively. `agy models` then exited 0 and reported these exact Gemini slugs for this account: `gemini-3.8-flash-high`, `gemini-3.8-flash-medium`, and `gemini-3.8-flash-low`. It also reported non-Gemini models; the plugin filters those out. The [Antigravity authentication guide](https://antigravity.google/docs/install) supports cached personal-account credentials for headless use and describes an API-key alternative that needs both `modelProvider: "gemini"` and `GEMINI_API_KEY`.
- The official [installer](https://antigravity.google/docs/getting-started?tab=cli) supplied `agy` 1.5.3. Its flags were checked with `agy --help`. The binary is installed at `~/.local/bin/agy` for the user's shell.

## Live transport evidence

A headless prompt in a temporary clean worktree used `--model gemini-3.8-flash-medium --output-format stream-json`. It emitted `init`, `step_update` records for user input, streamed response text, an `ACTIVE` and `DONE` `read_file` step with matching `step_index` and `tool_info.parameters`, and a `SUCCESS` result with `conversation_id` and token usage. The process exited 0. A second process used `--conversation <id>` and answered from the prior turn without rereading the file. The second result's token counts were cumulative across the conversation, while each completed step reported current-turn usage; the plugin sums completed-step usage for the displayed turn.

The committed `gemini-turn1.jsonl` and `gemini-turn2.jsonl` fixtures contain only whitelisted fields from these runs. Paths and conversation ID were replaced; credentials, home directory, account, plugin list, and skill list were excluded. `gemini-error.jsonl` records the `ERROR` result from an unknown model (exit 1).

## Capability limits

- The plugin respawns one headless process per turn and resumes by conversation ID. Text, tools, errors, completion, usage, and host process stop are supported. Only text prompts are accepted; it does not advertise images or live stdin steering.
- Headless approval requests are [soft-denied](https://antigravity.google/docs/cli/headless/#permissions-in-headless-mode) and cannot be answered through this stream. `--mode plan` and `--mode accept-edits` were accepted in live probes; `--mode auto` produced a warning that it is unavailable for this account, so the plugin does not use it. Full autonomy uses the documented `--dangerously-skip-permissions`. The plugin does not advertise live permission response or mode change.
- [Antigravity customization discovery](https://antigravity.google/docs/customization-discovery?tab=cli) documents workspace `.agents/skills/` and `.agents/mcp_config.json`. Abstract's current per-chat skill delivery and MCP configuration do not target those locations, so this plugin declares neither integration rather than writing to the user's global configuration or claiming unverified per-chat isolation.

All process execution remains with Abstract's host executor. The plugin script only builds launch arguments, parses lines, and asks the host to run `agy models` for account model discovery.
